MER Orientado a Objetivos: Por Que Modelar Assim?

Em HVAC-R, uma tabela não é apenas um repositório de dados: cada entidade reflete diretamente a física da refrigeração, o rigor legal do PMOC e a agilidade do mecânico em campo.

💻 A Visão do Desenvolvedor
  • Multi-tenant Nativo: Isolamento estrito de dados entre empresas prestadoras via RLS no Supabase.
  • Offline-First (🔭 proposta): Estrutura de dados pensada para sincronização assíncrona (subsolos e casas de máquinas).
  • Integridade Referencial: Foreign keys e estados que impedem ativos órfãos e dados contraditórios.
🔧 A Visão do Especialista
  • Foco na Máquina: Prontuário técnico vitalício com histórico de compressores, quebras e gás de fábrica.
  • Ciclo Termodinâmico: Registro claro de pressões de alta/baixa, superaquecimento e delta térmico ($\Delta T$).
  • Respaldo Legal: Laudos de PMOC (Lei 13.589/18) com evidências fotográficas e responsabilidade técnica.
🎯 O Objetivo do Negócio
  • Zero Papel: Fim de blocos de OS perdidos e falhas de cobrança de peças em campo.
  • Velocidade no Atendimento: Meta (estimativa, não medida): menos de 90 segundos para o mecânico lançar e disparar comprovante.
  • Conformidade Sem Fricção: Atende à lei sanitária sem travar o ritmo operacional da equipe.
💡 Princípio Central do MER: A entidade central é o EQUIPAMENTO, identificado via QR Code unívoco, ao redor do qual orbitam as ordens de serviço, medições e contratos.

🏢 Por Que Esta Estrutura Existe no Negócio?
  • Para a Manutenção: Evita a confusão de "qual split está quebrado". O chamado aponta: *Cliente Supermercado X -> Filial Sul -> Sala dos Servidores*.
  • Para o PMOC Legal: A legislação exige laudo por **ambiente climatizado**, discriminando a volumetria e pessoas no local.
  • Para os Desenvolvedores: A amarração em árvore permite agrupar manutenções preventivas em lote por rota de atendimento geográfica.
🛡️ Invariante Rígida: Toda máquina ativa pertence obrigatoriamente a um local_id. Não são permitidos equipamentos desvinculados de um espaço físico.

EQUIPAMENTO: O Prontuário Digital do Ativo

A máquina é o centro de gravidade da empresa de refrigeração. A etiqueta com QR Code conecta a física da condensadora/evaporadora ao banco de dados.

❄️ EQUIPAMENTO Tabela Principal
  • id : uuid PK
  • local_id : uuid FK -> LOCAL_INSTALACAO
  • qr_code_id : string (Unique) Index B-Tree
  • categoria : string Split, VRF, Chiller, Câmara Fria
  • fabricante / modelo : string Carrier, Daikin, Elgin
  • capacidade_btu : int Ex: 12.000, 60.000 (5 TR)
  • tipo_fluido : string R410A, R32, R404A, R22
  • tensao_eletrica : string 220V Mono, 380V Trifásico
📱 Em Campo (Mecânico)
  • Acesso Instantâneo: Apontou a câmera para o QR Code da máquina, o app carrega na hora: modelo, tipo de gás de fábrica e histórico.
  • Histórico de Quebras: Permite saber: *"Esse compressor já queimou 2 vezes este ano; não adianta só trocar o capacitor"*.
⚙️ Na Engenharia de Software
  • Busca Ultrarrápida: Campo qr_code_id unívoco e indexado, viabilizando busca local offline em cache IndexedDB (🔭 proposta).
  • Imutabilidade Técnica: O tipo de gás original e tensão não podem ser alterados sem flag explícita de Retrofit.
🎯 Objetivo do Negócio Atendido: Acabar com a dúvida de peças e fluidos incompatíveis. O técnico não carrega fluido errado para o atendimento.

ORDEM_SERVICO & TECNICO: Da Abertura ao Comprovante

Estrutura flexível que atende tanto chamados emergenciais quanto preventivas periódicas, com captura de evidências visuais e assinatura digital.

⚡ ORDEM_SERVICO Transação Operacional
  • id : uuid PK
  • equipamento_id : uuid FK -> EQUIPAMENTO
  • tecnico_id : uuid FK -> TECNICO
  • tipo : string Preventiva (PMOC), Corretiva, Avulsa
  • status : string Agendada, Em_Atendimento, Concluida
  • relato_cliente / diagnostico : text Linguagem natural ágil
  • foto_antes_url / foto_depois_url : string Storage S3/Supabase
  • assinatura_cliente_url : string Traço na tela / Validação
  • valor_total_servico : decimal Mão de obra + Peças
📸 Respaldo com Evidências
  • Fotos Antes/Depois: Mostram ao cliente a serpentina desobstruída e a bandeja limpa, eliminando contestações de cobrança.
  • Disparo no WhatsApp: Ao concluir, o sistema deverá gerar o comprovante com as fotos e dados (meta ilustrativa: menos de 10 segundos).
🔄 Flexibilidade de Estados
  • Lançamento Posterior Permitido: A OS pode ir de criação a conclusão no mesmo minuto (para quando o mecânico lança após fazer o serviço).
  • Imutabilidade Pós-Fechamento: Uma vez assinada e concluída, torna-se somente-leitura para garantir segurança jurídica.
🚀 Meta de Eficiência (estimativa): Permitir o preenchimento completo da OS em menos de 90 segundos na tela do celular do mecânico.

MEDICAO_TECNICA: Ciclo Frigorífico & Parâmetros Físicos

O diferencial que separa um software de refrigeração de um app genérico de manutenção predial: captura de pressões, temperaturas e corrente elétrica.

🌡️ MEDICAO_TECNICA Diagnóstico Físico
  • id : uuid PK
  • ordem_servico_id : uuid FK -> ORDEM_SERVICO
  • pressao_sucao_psi : float Linha de Baixa Pressão
  • pressao_descarga_psi : float Linha de Alta Pressão
  • temp_insuflamento_c : float Saída do Ar Gelado
  • temp_retorno_c : float Entrada do Ar Ambiente
  • delta_t_calculado : float Diferencial térmico (Retorno - Insuflamento)
  • corrente_operacao_a : float Consumo elétrico do compressor
  • superaquecimento_k : float Proteção contra retorno de líquido
🔬 Diagnóstico Especializado
  • Delta T ($\Delta T$): Se a diferença for menor que 8°C a 12°C em splits normais, o sistema sinaliza baixo rendimento térmico.
  • Pressões de Trabalho: Identifica na hora falta de gás, serpentina suja ou capilar entupido antes de condenar o compressor.
💻 Decisão de Arquitetura
  • Entidade Segregada (1:N): Permite medição antes do conserto e medição de pós-validação sem poluir a tabela de OS.
  • Campos Não Bloqueantes: O técnico pode registrar apenas o Delta T rápido ou pressões se não estiver com o manifold.
⚙️ Invariante Termodinâmica: Em compressores de pistão/scroll/rotativo: pressao_descarga > pressao_sucao. Especificação: o banco deverá rejeitar leituras invertidas (CHECK a implementar).

LAUDO_PMOC: Conformidade Sanitária & Rastreabilidade de Gás

Modelado para atender às normas da Anvisa e Ministério da Saúde, além do rastreamento de fluidos ecológicos conforme o Protocolo de Montreal.

📜 LAUDO_PMOC Conformidade Legal
  • id : uuid PK
  • ordem_servico_id : uuid FK -> ORDEM_SERVICO (1:1)
  • filtro_higienizado : boolean Obrigatório Portaria 3.523
  • dreno_desobstruido : boolean Prevenção de transbordamento
  • bandeja_limpa : boolean Controle bacteriológico
  • serpentina_quimica : boolean Aplicação de bactericida
  • vazamento_detectado : boolean Teste de estanqueidade
  • gas_adicionado_kg : float Balanço de massa de fluido
  • gas_recolhido_kg : float Destinação ecológica/recolhedora
🛡️ Segurança em Auditorias
  • Fiscalização da Anvisa: Deverá gerar laudos em PDF com o checklist sanitário completo, pronto para apresentar ao fiscal.
  • Controle de Gás: Não permite registrar recarga de gás sem indicar o teste de estanqueidade e solução de vazamento.
⚖️ Por Que Uma Tabela Separada?
  • Separação de Preocupações: Uma corretiva emergencial rápida não gera registro de PMOC, mantendo o banco normalizado e sem campos nulos inúteis.
  • Sem Retroatividade Falsa: Invariante de sistema que impede adulterar datas passadas para simular prazos de vistoria.
🌿 Sustentabilidade: O campo gas_recolhido_kg registra o uso de recolhedora em oficina, apoiando a comprovação de conformidade com normas ambientais do CONAMA.

CONTRATO: Automação das Preventivas e Previsibilidade

Como o banco de dados deverá automatizar a rotina da empresa, gerando ordens de serviço preventivas mensais sem esquecimentos e sem retrabalho manual.

📑 CONTRATO Automação Periódica
  • id : uuid PK
  • cliente_id : uuid FK -> CLIENTE
  • data_inicio / data_fim : date Vigência contratual
  • frequencia_pmoc_meses : int 1 (Mensal), 3 (Trimestral)
  • limite_corretivas_inclusas : int Chamados avulsos cobertos
  • responsavel_tecnico_id : uuid FK -> TECNICO (CREA/CFT)
  • ativo : boolean Flag de controle
📅 Benefício Operacional
  • Zero Esquecimento: No primeiro dia do mês, o sistema agenda automaticamente a visita para todos os aparelhos sob contrato.
  • Fidelização do Cliente: O contratante recebe certificados mensais de renovação do PMOC sem precisar cobrar a empresa.
🤖 Arquitetura de Automação
  • Supabase Edge Function / Cron: Dispara todo dia 1º de cada mês, criando as instâncias de ORDEM_SERVICO no status Agendada.
  • Vínculo N:N Contrato-Equipamentos: Tabela associativa que define quais máquinas estão contempladas no contrato vigente.
💼 Objetivo Comercial: Transformar serviços avulsos de "apagar incêndio" em contratos de receita recorrente mensal (MRR) previsível.
