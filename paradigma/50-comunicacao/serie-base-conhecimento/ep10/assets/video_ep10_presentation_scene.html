📝 A Ilusão do Spec-Driven: Markdown Amíguo vs. Intent IR

Por que trocar prompt solto por texto solto com bullet points não resolve o determinismo.

SLIDE 1/4
📄 GitHub Copilot Workspace: A "Spec" em Markdown
🔄
Texto Gerando Texto: Converte uma Issue em um texto em Markdown com bullet points. Continua sendo linguagem natural aberta e estocástica!
🎲
Não-Determinístico: Dois planos iguais podem gerar códigos completamente diferentes e com regressões silenciosas.
🙈
Cego para Bancos de Dados: Focado puramente em commits de arquivos de aplicação, sem diff semântico de tabelas.
🌲 IDD: A Intent IR (Árvore Sintática do Domínio)
📐
Representação Intermediária Tipada: A intenção é compilada para uma AST formal com contratos de tipo estritos e invariantes explícitas.
⚡
Compilação Determinística: Como na tradição LLVM/DSPy, a mesma intenção produz a mesma semântica verificável.
🏛️
Governança de Dados: O modelo relacional (MER) é o tribunal supremo inviolável da corporação.
🎲 Aider / SWE-bench: A Cultura "Patch-and-Pray"
🩹
Remendo e Reza: O modelo aplica um patch no arquivo Python/JS e roda a suíte de testes unitários (`pytest`).
⚠️
A Falácia do assert_equal: Testes unitários cobrem apenas amostras finitas conhecidas pelo programador.
⏰
O Bug das 3h da Manhã: Se o teste não previa concorrência ou corrida de dados, o patch passa no CI e quebra em produção!
📐 IDD: Prova Formal com SMT Solvers (Z3 & Dafny)
🛡️
Garantia Matemática Universal: Em vez de testar 3 exemplos, o provador formal analisa todo o espaço de estados possíveis.
🚫
Alucinação de Domínio Zero: Se a proposta do agente violar uma única regra de negócio, a compilação é abortada no ato.
✨
Software Inabalável: O código só chega à produção acompanhado da prova formal de não-violação.
🚫 Por que o Git é Cego para a IA?
- status VARCHAR(20)
+ status_id INT REFERENCES status(id)
