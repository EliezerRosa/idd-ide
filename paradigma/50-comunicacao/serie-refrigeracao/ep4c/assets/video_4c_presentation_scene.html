🔄 A Máquina de Diff de Intenções no IDD

Por que o Git não basta e como o IDD compara grafos semânticos de domínio em vez de texto.

⚠️ O Limite do Git e das Migrações Clássicas

No mundo convencional, alterações de código geram scripts cegos:

  • Diff Textual Cego: O Git só enxerga linhas alteradas, ignorando as regras de negócio.
  • Quebra Silenciosa: Um ALTER TABLE com NOT NULL quebra milhares de registros antigos no banco.
  • Alucinação de IA: Se a IA recompilar do zero, gera schemas incompatíveis com a base em produção.
🛡️ O Diff Semântico do Paradigma IDD

No IDD, a fonte primária da verdade é a Intenção:

  • Intent AST Graph: A máquina compara árvores de intenção entre a versão atual e a nova versão.
  • Impacto Transversal: Mapeia instantaneamente quais tabelas do MER, UCs e métodos são impactados.
  • Preservação Absoluta: Zero risco de perda de dados históricos ou corrupção de laudos auditáveis.
🟢 Classe A: Aditivas

100% Seguras e Compatíveis

  • Novos sub-módulos e Bounded Contexts.
  • Novos Casos de Uso de 2º Nível.
  • Colunas novas opcionais (NULL).
  • Compilação imediata sem impacto no legado.
🟡 Classe B: Endurecimento

Constraint Hardening

  • Regra de negócio que passa a ser estrita.
  • Exigência de nova portaria ou lei sanitária.
  • Requer Invariantes Temporizadas.
  • Passado permanece válido; futuro é travado.
🔴 Classe C: Estruturais

Breaking Changes

  • Mudança de cardinalidade (1:N para N:N).
  • Divisão ou fusão de entidades no MER.
  • Exige padrão Expand & Contract.
  • Dual-write e backfill sem downtime.
🔄 O Ciclo Operacional de 5 Etapas da Máquina de Diff

Protocolo determinístico antes de aplicar qualquer alteração sobre a base de dados de produção:

Etapa 1 Parsing AST Extração do grafo semântico da nova intenção.
Etapa 2 Raio de Impacto Mapeia tabelas do MER e UCs afetados.
Etapa 3 Plano IMP Intent Migration Plan legível para aprovação.
Etapa 4 Síntese DDL Geração de migração Expand & Contract.
Etapa 5 Não-Regressão Bateria de testes provando zero dados corrompidos.
📋 A Vitória da Governança Contínua

O software evolui com a empresa ao longo dos anos:

  • Human-in-the-Loop Gate: O gestor aprova o plano de migração antes da execução da IA.
  • Rastreabilidade Total: Cada versão do schema é ancorada em uma versão formal de intenção.
  • Zero Degeneração: O código não vira espaguete com o passar do tempo.
🚀 Próximo Passo: Episódio 4D

No Episódio 4D nós veremos a solução matemática da atomicidade temporal:

  • Invariantes Temporizadas: Preservação de dados antigos sob novas leis.
  • Expand and Contract: Dual-write e migração sem downtime.
  • Validação de Campo: Como a climatização opera com segurança total.
