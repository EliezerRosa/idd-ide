⏳ O Dilema da Nova Regra Ambiental vs Dados Legados

Como aplicar uma regra nova sem invalidar milhares de manutenções históricas.

SLIDE 1 / 4
⚠️ O Risco do Modelo Convencional
Trava rígida retroativa: adicionar NOT NULL direto no banco quebra milhares de ordens históricas.
Corrupção e inconsistência em relatórios fiscais antigos que não possuíam o novo campo exigido.
Paralisação do sistema ou preenchimento falso com dados artificiais (dummy data).
🛡️ A Solução IDD: Guardas Temporais
Invariante Temporizada: a regra estrita só passa a valer para registros criados após a vigência legal.
O passado continua juridicamente impecável sob as normas da sua respectiva época.
O presente adota conformidade imediata sem intervenção manual perigosa no banco de dados.
💡
Princípio IDD da Imutabilidade Histórica: O software evolui declarativamente sem apagar nem violar a verdade factual dos eventos de negócio registrados no passado.
INVARIANT ValidaRecargaGasRefrigerante(os: OrdemServico) {
  IF os.dataCriacao < 2026-01-01 THEN
    RETURN os.gasKg > 0 AND os.tecnicoResponsavel != null // Regra Clássica Legada
  ELSE
    RETURN os.gasKg > 0 AND os.balancaCalibradaNumero != null AND os.balancaCalibradaNumero.isValid() // Regra Estrita
}
1️⃣ Fase 1: Expandir
Cria a nova coluna ou relação no banco como opcional. A aplicação escreve no modelo antigo e no modelo novo simultaneamente.
2️⃣ Fase 2: Sincronizar
Backfill determinístico em lote. A IA migra dados históricos com idempotência e validação semântica ponto a ponto.
3️⃣ Fase 3: Contrair
Remove as colunas obsoletas somente após 100% de trânsito estável e suíte de não-regressão aprovada.
